# NetSage v2.0 路线图 · 6 个月重大版本

> **主题**：消除所有 🟡 标记，进入 SaaS-ready 阶段  
> **时间窗口**：6 个月（2026-10 ~ 2027-03）  
> **版本**：v2.0.0（major · 第一个真正可销售给企业生产环境的版本）  
> **前置条件**：v1.0.2 已发布且 release gate 全过  
> **与 v1.0.1 关系**：v1.0.1 承认了 5 项 🟡，v2.0 必须全部转 ✅

---

## 一、v2.0 的定义（远景）

### 1.1 一句话

NetSage v2.0 = v1.0.1 全部承诺落地 + 多租户 SaaS 化 + 第三方安全审计 + 商业模型可计费。

### 1.2 远景

不是 demo，不是技术预览，不是承诺 vs 实际有 gap。是 **企业愿意按月付费的真实产品**。

### 1.3 v2.0 与之前版本的边界

| 版本 | 性质 | 完成度 |
|---|---|---|
| v0.1.x | 平台骨架 | 仅 Phase 1+2 |
| v1.0.0 | 生产化 | 5 项 🟡 承认但未交付 |
| v1.0.1 | 审计修复 | 12 ✅ / 5 / 3，但 RDMA/RAG/OIDC/Wireless/评测集仍是 🟡 |
| **v2.0** | **真生产** | **0 🟡 + 多租户 + 商业化 + 安全背书** |

### 2.1 质量 KPI

| 指标 | v1.0.1 现状 | v2.0 目标 |
|---|---|---|
| 月活 Pilot 客户 | 0 | ≥ 2 |

## 三、阶段分解

### 阶段 1：去 🟡（M1-M3，3 个月）

**主题**：把 v1.0.1 的 5 个 🟡 全部转 ✅

#### 任务表

| 任务 | 时间 | 责任方 | 验收 |
|---|---|---|---|
| **RDMA 真实硬件 POC** | M1 | Tech Lead + IB 客户 | OpenSM-MCP OPENSM_MOCK=false 跑真实 2 节点 4 端口 IB fabric，附报告 + 截图 |
| **OIDC Keycloak E2E** | M1-M2 | AI 工程师 | 跑 Keycloak 实例 22.x，完成端到端 SSO 测试套件 |
| **Wireless WLC API 接入** | M2-M3 | 厂商协作者 | WirelessAgent 生成配置 → 通过 WLC API 下发 → 验证 AP 接入 |
| **RAG 语料补全** | M1-M3 | Tech Lead（标注主力）| ingest 1 家思科 + H3C + Junos 手册（需 NDA）+ RFC 2328/4271/4456/7296/7938 全文 |
| **评测集人工复审** | M1-M3 | Tech Lead（标注主力）| 402 题逐题人工复核并补 grading_rubric |
| **CLI nsc v1** | M1 | AI 工程师（v1.0.2 收尾）| 5 个命令 + 30 测试 |
| **frontend 真实部署** | M1 | AI 工程师 | Dockerfile + 生产 nginx + healthcheck |
| **评测集质量复审 200+** | M1-M2 | Tech Lead + AI 工程师 | auto_generated 200 题逐题改/或删 |

#### 阶段 1 exit criteria

- 5 项 🟡 全部转 ✅
- 1 个付费 pilot 客户部署 v2.0-alpha
- 复审 200+ 评测题
- RAG 全量 hit_rate ≥ 70%（里程碑，不强制 85%）

#### 阶段 1 资源

| 角色 | FTE | 说明 |
|---|---|---|
| Tech Lead | 1.0 | 客户对接 + 评测标注 + 架构决策 |
| AI 工程师 | 1.0 | Agent / RAG / LLM / 测试 |
| 后端工程师 | 1.0 | 设备接入 / MCP / DB / Keycloak 部署 |
| 前端工程师 | 0.5 | Web Console / 报表 / WLC |
| **合计** | **3.5** | |

### 阶段 2：多租户 SaaS 化（M4-M5，2 个月）

**主题**：从单租户 hack → 真正的多租户架构

#### 任务表

| 任务 | 时间 | 验收 |
|---|---|---|
| **Tenant 资源配额** | M4 | 每个 tenant 有 LLM 配额、并发数、存储上限 |
| **API Key + RBAC per tenant** | M4 | 每个 tenant 独立 API key + 角色 |
| **LLM 网关 per tenant** | M4 | 难度路由 + 缓存 + 用量统计全 per-tenant |
| **计费 & 计量** | M5 | 用量埋点 → 计费事件流 → 发票生成 |
| **SLA 仪表盘** | M5 | 99.9% 可用性 SLO + 错误预算监控 |
| **多 region 部署** | M5 | K8s 多集群 + 跨 region 数据库复制 |

#### 阶段 2 exit criteria

- 5 个并发 pilot 客户
- 计费可对账（金额可核对到单条 LLM 调用）
- SLA 可监控（P95 延迟 + 错误率 + 配额）
- 跨 region 至少 1 次 DR 演练通过

#### 阶段 2 资源

| 角色 | FTE | 说明 |
|---|---|---|
| Tech Lead | 1.0 | 架构 + 客户 |
| AI 工程师 | 1.5 | 多租户 LLM 配额 + 计量 |
| 后端工程师 | 1.5 | K8s 多集群 + DB 复制 |
| 前端工程师 | 0.5 | 计费仪表盘 |
| SRE | 0.5 | DR 演练 + 监控 |
| **合计** | **5.0** | |

## 六、风险登记

| 风险 | 等级 | 缓解 |
|---|---|---|
| 找 1 家客户做 RDMA POC（IB 硬件稀缺） | 🔴 高 | 提前联系 2-3 家 RDMA 用户，提前签 NDA |

## 七、v2.0 成功标志

### 7.1 GA 当日（2027-03-31）

- 5+ 付费 pilot 客户
- MRR ≥ 10 万
- 公开 benchmark 论文 / 博客 ≥ 2 篇
- 厂商生态合作 ≥ 1 家（华为 / 思科 / NVIDIA 任一）
- 团队 5+ FTE 健康运转
- 5 项 🟡 全部 ✅

### 7.2 6 个月回顾

- 客户满意度 NPS ≥ 30
- 工单 MTTR < 4h
- 系统可用性 ≥ 99.9%（按月算）
- 安全事件 0 起（第三方审计 + bug bounty 启动后）

## 八、v2.0 不做（明确边界）

- ❌ 自研 LLM（不切训练）
- ❌ 移动 App（只做 Web）
- ❌ 网络设备硬件销售
- ❌ 自有 SDN 控制器
- ❌ 端到端 5G 核心网（无线只到 WLC 接入）
- ❌ 端到端云原生 K8s 网络（Cilium / Calico 集成暂缓）
