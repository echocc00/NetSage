## 一、项目定位与北极星指标

### 1.1 三句话定位

1. **资深网络工程师的"AI 结对伙伴"**：1 个 NetSage ≈ 1 个随时在线、熟读所有厂商手册、记住每条历史变更的 L4 工程师。
2. **业务驱动的网络架构师**：从业务 SLO（延迟、吞吐、合规、容灾）反推网络拓扑、协议选型、容量规划与安全策略。
3. **可执行、可审计、可回滚**：输出不是"建议"，而是带命令、带配置、带变更单的"可交付件"，所有动作进入审计流。

### 1.2 北极星指标

| 维度 | 指标 | 目标 |
|---|---|---|
| 效率 | P1 故障 MTTR 缩短 | -50% |
| 效率 | 架构设计 / 方案输出时间 | -70% |
| 质量 | 配置变更首次通过率 | ≥ 95% |
| 覆盖 | 主流厂商协议覆盖 | OSPF/BGP/VXLAN-VPN/IPSec/RoCE ≥ 90% 场景 |
| 信任 | 幻觉率（事实性错误） | ≤ 2%，可引用 |
| 闭环 | 故障场景端到端闭环 | ≥ 80% |

### 3.2 端到端一次请求的旅程（示例：用户问"数据中心两台 Spine 之间 BGP 邻居反复抖动，可能原因？"）

1. **交互层**：Web IDE 接收用户提问，附带已选上下文（当前设备、当前 VRF、最近告警）。
2. **路由器**：识别意图 = "故障排查" + 场景 = "BGP" + 优先级 = "高"。
3. **规划器**：拉起 Troubleshooter Agent，编排以下步骤：
   - 拉取目标设备的 NETCONF 状态（hold-time、established counter、last-reset reason）。
   - 拉取最近 24h 的 BGP 相关 syslog + NetFlow 异常。
   - 调用 RAG 检索"BGP 抖动 常见原因"（按厂商+版本命中权威条目）。
   - 调用 Topology 分析生成"这两台 Spine 的全路径图"+"中间链路光模块/CRC 历史"。
4. **工具执行**：并行调用 SSH/NETCONF/日志查询。
5. **反思器**：基于检索内容 + 工具结果，生成 3 个候选根因 + 证据链 + 验证步骤。
6. **输出**：结构化报告 + 跳转链接到 NetBox 设备页 + 一键生成变更工单。

## 四、知识库与 RAG 设计

### 4.1 知识分层

| 层级 | 内容 | 来源 | 检索权重 |
|---|---|---|---|
| L1 官方手册 | 华为 VRP / Cisco IOS-XE/NX-OS / H3C Comware / Juniper Junos / Arista EOS / Nokia SR OS / Mellanox Onyx 官方配置手册、命令参考、Release Notes | 厂商官网/产品包 | ★★★★★ |
| L2 标准协议 | RFC 2328/4271/7348/8365/9136 等关键 RFC；IEEE 802.11ax/be；IBTA RoCE v1/v2 | IETF/IEEE/IBTA | ★★★★★ |
| L3 最佳实践 | Cisco CVD、Juniper Validated Design、RFC 草案、Tech Field Day 报告 | 厂商白皮书/社区 | ★★★★ |
| L4 内部资产 | 内部 HLD/LLD、变更单、Postmortem、巡检报告、配置模板库 | 内部 Git/Confluence | ★★★★★ |
| L5 实时状态 | 设备 running-config、NetBox 拓扑、实时日志/指标 | 内部系统 | ★★★★ |

### 4.2 文档分块策略

- **手册类**：按"特性 → 场景 → 命令 → 注意事项"四级层级分块，每块不超过 1500 token，保留章节路径作为元数据。
- **命令参考**：按"命令名 → 视图 → 参数 → 示例 → 关联命令"结构化（JSON Schema 化）。
- **故障案例（Postmortem）**：按"症状 → 排查过程 → 根因 → 修复 → 经验教训"分块，标签化。
- **图谱**：拓扑图、协议图、设备互联图走多模态嵌入（CLIP + OCR），可被"画一张这个"指令调用。

### 4.3 检索策略

- **混合检索**：BM25（精确命令/错误码）+ 向量（语义）。
- **查询改写**：基于网络领域同义词表（OSPF Neighbor ↔ OSPF Adjacency ↔ OSPF Peer）。
- **多路召回**：原始 query + 改写 query + 假设答案（HyDE）三条路并行。
- **重排序**：bge-reranker-v2-m3 或厂商定制 ranker。
- **引用溯源**：每个事实段落必须带回来源 URL + 文档版本 + 抓取时间。
- **反馈闭环**：人工点赞/点踩 → 写入微调集 + 提升/降低该 chunk 权重。

### 4.4 知识保鲜

- 厂商 Release Notes 抓取（每周 cron），差异分析 → 主动告警"以下 3 个常用特性已废弃"。
- 内部 Postmortem 入库前 PII 脱敏 + 摘要。
- 配置模板库以 GitOps 方式管理，PR 审核后入库。

## 五、AI Agent 设计

### 5.1 专家 Agent 矩阵

| Agent | 输入 | 输出 | 工具 | 评测集 |
|---|---|---|---|---|
| **Architect** | 业务需求/容量/SLO/合规 | HLD + 拓扑图 + 协议选型论证 + 风险清单 | 拓扑分析、容量模型、成本估算 | 100 个真实架构题 |
| **ConfigEngineer** | 设计意图 + 设备型号 + 版本 | 完整配置 diff + 变更说明 + 回滚 | 模板库、YANG 模型、命令生成器 | 厂商命令覆盖率、首过通过率 |
| **Troubleshooter** | 现象/日志/指标/配置 | 根因假设 + 证据链 + 验证步骤 + 修复命令 | 设备查询、日志解析、NetFlow 分析 | 故障库命中率、误诊率 |
| **PerfAnalyst** | 流量/计数器/丢包/延迟 | 瓶颈定位 + 优化建议 + 容量预测 | Telemetry、Prometheus、RoCE 计数器 | 设计 vs 实测偏差 |
| **SecurityAuditor** | 配置 + 拓扑 + 威胁模型 | 漏洞清单 + 加固方案 + 合规对照 | CVE 库、配置扫描、策略检查 | 漏洞漏报率、合规通过率 |
| **DocWriter** | 工程产出物 | HLD/LLD/Runbook/Postmortem/SOP | 文档模板、图表生成 | 评审一次通过率 |

### 5.2 编排模式

- **Plan-and-Execute**：复杂任务先出计划 → 用户批准 → 执行。
- **ReAct**：轻量排查循环（Thought → Action → Observation）。
- **Multi-Agent Debate**：架构/配置/安全三方对同一方案互评，出具更稳健结论。
- **HITL 强制点**：所有"写"操作（配置下发、变更单提交）必须人工确认。

### 5.3 推理与上下文工程

- **长上下文**：设备级状态全量装载（≤ 200K token），跨设备走"摘要 + 指针"。
- **协议领域 prompt 模板**：
  - 角色（资深 X 厂商工程师）
  - 上下文（拓扑/版本/特征）
  - 输出格式（结构化 JSON / Markdown）
  - 约束（"不得编造命令"、"必须引用来源"）
- **Few-shot 注入**：每个 Agent 预置 5-10 个典型案例。
- **Self-Consistency**：关键结论多次采样投票。

### 5.4 模型策略

- **基座**：Claude / GPT-4 同级别通用模型作为推理核心。
- **私域模型**：Qwen2.5-72B / DeepSeek-V3 微调版，覆盖国产化合规场景。
- **Embedding**：bge-large-zh-v1.5（中文）+ bge-large-en-v1.5（英文）。
- **路由**：按任务难度路由（简单问答走小模型省钱，复杂推理走大模型）。

### 6.3 工具执行安全

- **白名单**：所有写操作（config 下发、变更单提交）经工具调用必须经过"审批服务"中间件。
- **Dry-run 默认**：所有生成类操作默认只产出，不下发。
- **会话隔离**：每个用户/工单独立的执行上下文，凭证走 Vault 注入。
- **回滚保证**：所有下发动作自动生成 rollback 配置，校验成功后保存 7 天。

## 七、关键场景工作流（精选 6 个）

### 7.1 场景 1：业务驱动的架构设计

**输入**：业务方提出"在西安数据中心新建 1000 节点 AI 训练集群，跨域到北京，要求 RDMA 训练延迟 < 5μs"。

**工作流**：
1. Architect Agent 分析需求 → 提取 SLO（延迟 5μs、带宽、容灾）。
2. 检索 RAG：RoCE v2 + 拥塞控制（PFC + ECN + DCQCN）+ 跨域 DCI 方案。
3. 调用 `impact_analysis` 评估现有拓扑承载力。
4. 输出 HLD：
   - 拓扑：Spine-Leaf，100G/400G NDR，AI 集群独立 Pod。
   - 协议：Underlay OSPF/ECMP + Overlay EVPN-VXLAN + 跨域 BGP-EVPN。
   - RDMA：PFC + ECN 队列映射 + DCQCN 调参建议。
   - 安全：微分段 + MACsec + 设备身份认证。
5. ConfigEngineer 生成核心设备配置模板。
6. SecurityAuditor 出具合规与风险报告。
7. DocWriter 整合 HLD + 风险 + 成本 + 实施计划。

### 7.2 场景 2：MPLS L3VPN 跨域配置生成

**输入**：CE1-PE1-P-CE2（Option A），CE 跑 OSPF，PE 跑 MP-BGP VPNv4。

**工作流**：
1. 识别厂商（华为 NE40E）和版本（VRP 8.x）。
2. 检索 RAG 命中 NE40E 配置手册对应章节。
3. 生成配置：
   - PE 端：MPLS LDP / OSPF sham-link / MP-BGP vpnv4 邻居 / VRF + 路由区分符。
   - CE 端：OSPF area + 双向重发布。
4. SecAudit 检查：MD5 鉴权、TTL 传播、控制平面保护。
5. 模拟：在 CML 拉起 4 节点拓扑，灌配置，验证邻居/路由/连通性。

### 7.3 场景 3：OSPF Neighbor 频繁震荡

**输入**：`%OSPF-5-ADJCHG: ...  to DOWN, Neighbor died: Hello timer expired`。

**工作流**：
1. Troubleshooter 抓取：
   - 两端 OSPF Hello/Dead、Pacing、Network Type、Authentication。
   - 物理端口 CRC、输入错误、光模块收发光。
   - 最近 1h 输入丢包、stp 状态、QoS 拥塞丢包。
2. 候选根因：根据 RAG + 实时数据排序：
   - 优先级 1：网络类型不一致（broadcast vs p2p），Hello 10s vs 30s。
   - 优先级 2：MD5 鉴权 key mismatch。
   - 优先级 3：接口 MTU 不一致 → DD 重传 → Hold 超时。
   - 优先级 4：物理 CRC 异常导致 hello 丢包。
3. 为每个假设提供"验证一步操作 + 修复命令"。
4. 一键生成变更单（含回滚）。

### 7.4 场景 4：VXLAN EVPN Type-2/Type-3 路由不通

**输入**：同租户跨 Leaf 通信异常，Type-2 MAC/IP 路由缺失。

**工作流**：
1. 检查子协议：BGP EVPN 邻居、VNI、本地 ARP 表、远端 MAC 表。
2. 调用 `query_flows` 抓 VXLAN 封装包路径。
3. RAG 命中"Type-2 路由通告抑制"、"anycast-gateway 冲突"、"ARP flood suppress"。
4. 给出修复：调整 bgp evpn 路由器通告策略 / 启用 gw-irb / 重置 suppress。

### 7.5 场景 5：RoCE v2 性能不达标

**输入**：训练任务实测 P99 延迟 18μs，超过 SLO 5μs。

**工作流**：
1. PerfAnalyst 抓 PFC/ECN 计数器、CNP 包、DCQCN 状态、队列长度。
2. 识别：PFC storm、ECN 阈值不合理、LLR/DCQCN 调参未启。
3. 给出调优清单：PFC 优先级映射、ECN 水线、buffer 分配、QoS 模版。
4. 模拟：基于硬件仿真或 CML 验证。

### 7.6 场景 6：变更前安全审计

**输入**：即将下发 200 台设备的 BGP 配置。

**工作流**：
1. SecurityAuditor 解析所有配置 diff。
2. 检查项：
   - peer 鉴权（MD5/AH）
   - GTSM（TTL 安全）
   - 最大前缀数
   - 路由策略黑洞
   - 设备管理面加固
   - VRF 隔离
3. 输出风险清单 + 阻断式门禁（Critical 阻断，Warning 警示）。

## 九、安全与合规

### 9.1 核心原则

- **最小权限**：默认只读，敏感操作走审批。
- **零信任**：所有 API 调用 + mTLS + OIDC。
- **全审计**：所有动作带 user、device、command、before/after、timestamp。
- **数据脱敏**：配置中敏感字段（密码、SNMP community）写入日志前自动 mask。
- **数据不出域**：核心数据（topology、config）保留在本地，外部 LLM 仅传最少的必要片段。

### 9.2 部署形态

| 模式 | 适用 | 风险 |
|---|---|---|
| 全公有云 | PoC | 高（数据外泄） |
| 混合云（推理外，数据内） | 通用 | 中 |
| 全私有化（本地 LLM + 本地知识库） | 高敏感/国产化 | 低（成本高） |

### 9.3 合规对照

- **等保 2.0**：三权分立（系统管理员 / 安全管理员 / 审计管理员）。
- **数据安全法 / 个保法**：操作日志保留 ≥ 6 个月。
- **行业规范**：金融行业"两地三中心"、运营商"关基"要求。

## 十二、风险与缓解

| 风险 | 等级 | 缓解措施 |
|---|---|---|
| LLM 幻觉导致错误配置 | 高 | 强制工具调用 + 命令校验 + 灰度 dry-run + 严格审计 |
| 厂商配置覆盖不全 | 高 | 优先 Top 3 厂商 + 模板库 + 用户共建 |
| 内部敏感数据外泄 | 高 | 私有化部署 + 字段脱敏 + DLP 审计 |
| 工具执行不可控 | 中 | 沙箱 + 审批 + 灰度 + 自动回滚 |
| 检索召回不足 | 中 | 混合检索 + 重排序 + 反馈闭环 + 持续抓取 |
| 用户信任建立慢 | 中 | 先小场景高成功 → 扩展；透明可解释 |
| 模型成本失控 | 中 | 难度路由 + 缓存 + 小模型兜底 |
| 团队能力（懂网络 + 懂 AI）稀缺 | 中 | 与网络专家深度结对（你本人）；AI 工程师从基础协议学起 |
| 跨厂商知识库长期维护 | 中 | 文档版本监测 + 自动 diff + 主动通知 |
